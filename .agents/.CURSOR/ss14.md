Living notes about how upstream Space Station 14 is structured. Expand as we learn more.

## ECS quick map

- **Entities** = ID + set of components.
- **Components** = data only (`[RegisterComponent]`, often `[NetworkedComponent]` + `[AutoGenerateComponentState]`).
- **Systems** = logic (`EntitySystem`, event handlers).
- Shared systems run on both sides when prediction/replication needs it; server-only for authoritative rules.

Prototypes (`IPrototype`, `[Prototype("kind")]`) are data-driven definitions loaded from `Resources/Prototypes/**/*.yml`.

## Melee sounds

Swing and hit audio are data on `MeleeWeaponComponent` (`soundSwing`, `soundHit`), played by `MeleeSoundSystem`. A miss plays the swing. A hit plays the hit sound, unless the target's `MeleeSoundComponent` has a sound for that damage group. Setting `MeleeHitEvent.Handled` returns before the hit sound, so a system that replaces damage has to play it.

## Late `MsgEntity`

`net.ent: Got late MsgEntity` is `net.log_late_msg` (on by default). It is a client **input** whose source tick is behind the server tick. The server still queues and applies it (`SourceTick <= CurTick`). It is not a dropped entity-state diff. `Diff -7` at 30 ticks/s is about 0.23s of server stall. `subTick` is a fraction of one tick, and `func` is a keybind id. A local server prints this when a tick runs long, then catches up. A dying body still slides in the physics step. That move does not schedule flanking. The dying recovery check runs once per game tick.

## Client UI

- Robust UI is XAML + code-behind (`*.xaml` / `*.xaml.cs`), similar to Avalonia.
- `[GenerateTypedNameReferences]` generates typed accessors for named XAML controls.
- `RobustXamlLoader.Load(this)` is replaced at build time by XamlIL with the precompiled populate method. If you see `No precompiled XAML found for …`, the XAML was not compiled onto that type (wrong `x:Class` / path, or stock XAML still colliding).
- `UIController` types (e.g. `LobbyUIController`) own lobby/setup windows. Many are `sealed`; prefer CF overlays over editing them.

## Game HUD

The in-game bar is `Content.Client/_CF/Hud/CFGameHud`. It sits on the default and separated-chat screens. Hit points, temporary hit points, and Armor Class come from `CFCombatantComponent`. Spell pips and focus come from `CFSpellbookComponent`, filled at spawn from the class (`CFSpellSlots`) and any slots marked expended on the sheet. Cantrips are at-will and are not drawn as pips. The action grid is two rows of the hotbar keys. The emote wheel (`CFRadialMenu`) is vocal chat, actions, free actions, cantrips, and spell ranks. Reactions are not on the wheel; each one is resolved in code when its trigger happens. `CFActionPoolComponent` is that creature's action stamina: one action spends `StaminaPerAction` (default 1), one point returns every `RegenSeconds` (default 1.8), and `MaxActions` (default 3) can be raised with `CFActionPoolSystem.SetMaxActions` for haste or a potion. Multiple Attack Penalty is `MapAttacks` on that pool, not the number of actions left: only a strike or a spell attack roll increases it, a cantrip does not, and it clears when the pool is full again. The next roll is −5 then −10, or −4 then −8 when the weapon has `Agile` (fists do). This is separate from SS14 `StaminaComponent`, which paralyzes at its cap. An action appears on that wheel only when it has `CFRadialSlotComponent`. Belt, bag, pockets, suit storage, and the ID slot (the PDA) use slot groups `CFBelt`, `CFBag`, `CFPockets`, `CFSuitStorage`, and `CFId`. Hand buttons are on this HUD. The stock hotbar strip, including both item status panels, stays hidden. Open bags still attach to that widget, above the HUD.

Known spells are granted as actions at spawn when `Resources/Prototypes/_CF/Spells/CF{Id}.yml` exists. The wheel casts them. Spell actions set `raiseOnAction`, because the cast event is otherwise raised on the caster and a `CFSpellComponent` subscription on the action never runs. A projectile spell then tracks the creature you click (`CFHomingProjectileComponent`), instead of flying in a straight line. Force Barrage asks for 1, 2, or 3 bolts first, stores them, and sends one per click so they can hit different creatures or the same one. Each bolt is 1d4+1 force, and the cast spends one spell slot. The hotbar click uses the same choice menu as the radial wheel. While aiming, a creature inside the spell's range is outlined green and one past that range is outlined red. Nothing farther than 90 feet, or behind a wall, is outlined. Prestidigitation asks for Food, Lift, Make, or Tidy and spends its two actions when the trick lands. Food checks the clicked entity for `EdibleComponent`, heats raw food with `SetCookedTemperature` so the interior is hot before the construction cook step runs, and adds the `cfMagical` flavor (`Tastes of magical flavours.`). A cooked replacement keeps that flavor through `ConstructionChangeEntityEvent`. Lift ignores mobs and stacks, picks into a free hand, or starts a pull. Make rolls `AllToysTable` into a free hand or onto the ground. Tidy deletes a puddle and spawns `PuddleSparkle`, the same end state as a mop that has emptied it. Object tricks do not use the creature outline. Area spells use the map grid at 1 tile = 5 feet (not the 1.25 melee reach): the outline follows the cursor, and the second click affects creatures in those tiles who are not in your party. Reflex, Fortitude, and Will are rolled by the spell system. Basic saves use the remaster degrees (none / half / full / double). Catalog names follow the remaster (Force Barrage, Floating Flame, Laughing Fit, Know the Way, Sure Strike, Needle Darts, Phase Bolt).

## Lobby / character setup

Upstream lives under `Content.Client/Lobby/`:

- `LobbyState`, `LobbyUIController` — state + open/save character setup
- `UI/HumanoidProfileEditor.*` — character editor (partial class split across Appearance, Roles, Traits, …)
- `UI/CharacterSetupGui.*` — slot picker wrapping the profile editor
- `UI/Loadouts/`, `UI/Roles/`, `UI/ProfileEditorControls/` — supporting controls

`LobbyUIController.EnsureGui()` constructs `HumanoidProfileEditor` and nests it in `CharacterSetupGui`. Keeping that public API stable lets CF replace only the editor UI without touching the controller.

## Prototypes & locale

- YAML under `Resources/Prototypes/` (CF: `Resources/Prototypes/_CF/`).
- Fluent locale under `Resources/Locale/en-US/` (CF: `Resources/Locale/en-US/_CF/`).
- Loc keys referenced as `{Loc 'key'}` in XAML or `Loc.GetString("key")` in C#.

## Upstream sync hygiene

- Prefer zero diffs in stock `Content.*/` trees outside `_CF/`.
- Compare Lobby (and similar) against `upstream/master` when checking accidental hub edits.
- Project-file `Compile Remove` / `EmbeddedResource Remove` / `AdditionalFiles Remove` can swap a stock type for a `_CF` replacement without editing the stock file body.
